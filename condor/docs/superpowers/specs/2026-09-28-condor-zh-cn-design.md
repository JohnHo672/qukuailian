# Condor 全站简体中文与英文切换设计

日期：2026-09-28

## 目标与边界

- Condor 网页首次打开默认显示简体中文（`zh-CN`），用户可以在全站页眉切换为英文（`en`）；刷新和重新打开后保持选择。
- 覆盖网页自身生成的全部可见文字：导航、页面标题、表格列名、图表标签、表单、占位文字、弹窗、确认与危险操作提示、空状态、加载与错误状态、通知、工具提示及无障碍标签。
- 不改变 Hummingbot API、下单逻辑、账户/机器人配置、认证方式或本机绑定端口。本地化不自动创建密钥、机器人或订单。
- 品牌名 Condor、币对、交易所名称、订单 ID、代码/YAML 字段、用户输入、外部返回的标识符保留原文。AI 回复和用户对话内容不自动翻译。
- 已知的 API 错误按稳定错误码映射成中文；未知错误在中文界面显示中文摘要，并提供可展开的原始技术详情，避免翻译造成误导。

## 方案选择

使用 `i18next` 与 `react-i18next` 管理翻译资源，而不是浏览器自动翻译或直接替换英文字符串。其 React hook、插值和复数机制适合当前组件式前端；英文作为完整回退语言。版本由 `package-lock.json` 锁定，翻译文件随 Condor 源码和静态构建一起交付，不依赖在线翻译服务。

## 架构和组件

1. `frontend/src/i18n/` 集中初始化语言、保存/读取用户选择并定义 `zh-CN` 和 `en` 的翻译资源。资源按 shell、agents、trade、dex、portfolio、bots、routines、settings、shared 等页面域拆分，共用术语放在 shared。
2. 首次加载固定 `zh-CN`，不按浏览器语言自动改变。只接受 `zh-CN` 或 `en` 的本地存储值；非法值回退 `zh-CN`。切换时即时更新界面和 `<html lang>`，不重新加载页面或重置交易操作状态。
3. 页眉提供清晰的“简体中文 / English”切换控件；窄屏仍可操作，键盘和屏幕阅读器能识别当前语言。
4. 组件使用语义稳定的翻译键，不以整句英文作键。变量通过插值传入；含链接或强调的句子用富文本翻译机制，避免拆句后中文语序错误。交易动作采用统一术语表，例如“下单”“撤单”“停止机器人”“仅减仓”。
5. 格式化日期和数字时使用当前语言，但不改变价格精度、数量、货币单位、正负号或后端参数。技术标识不本地化。

## 覆盖与验证

- 先建立两套键值和缺失键检查，再逐个迁移路由及共享组件。不能只翻译导航而留下按钮、弹窗或确认文字为英文。
- 对每个页面检查中文/英文、刷新保留选择、空/加载/错误状态、危险操作确认、键盘操作和窄屏布局；英文回退不得出现键名。
- 自动检查两种语言的键集合一致，构建与前端测试通过；针对交易和风险词汇增加断言，避免“买/卖”“启用/停止”方向翻错。
- 部署时只重建并重启 Condor 网页服务，保留旧静态构建以便回退；不重启 Hummingbot API、数据库、消息服务或原有 OKX 程序。上线后实测本机 `127.0.0.1:8088` 和 `127.0.0.1:18000`，确认账户凭据与机器人数量不变。

## 验收标准

用户在无历史语言设置的浏览器打开任何 Condor 页面，能看到简体中文；切为英文后全站即时切换并在刷新后保持。所有 Condor 自身文字均被覆盖，未翻译的外部数据明确属于边界；交易含义、数值、接口行为及本机访问限制与修改前一致。
